# BUG-2026-11-16T17:30:00: Idle CPU at ~55% due to unthrottled frame callbacks

## Problem

eswm idle CPU is ~55% (one core pegged, rising over time) and RSS is ~286 MB growing,
vs Hyprland's 1.9% / 84 MB flat. Memory is stable (VmHWM == RSS). It is not a leak. It is a hot loop keeping one core busy and accumulating resident pages.

Actual behavior: eswm renders continuously even on an idle desktop with no client windows.
Expected behavior: eswm should render at ~0% CPU when nothing has changed (idle desktop).

How to reproduce: start eswm on a bare TTY, run waybar or another client that requests
frame callbacks, observe CPU staying elevated even when the client is visually idle.

## Root Cause Analysis

The e05s04 changes added a `redraw_needed` flag to gate rendering, which correctly skips
page-flips when nothing changed. However, `frame_callbacks` sent callbacks to every drawn
surface on every render, unthrottled. A client like waybar that requests a frame callback
after each commit enters a commit/frame-callback loop:

1. Client commits a buffer
2. eswm renders the frame and sends a frame callback
3. Client receives the callback and commits again
4. Repeat at refresh rate (~60 Hz)

Each iteration sets `redraw_needed = true`, so the render loop never idles. The dirty flag
(e05s03) prevents redundant layout, but the render itself still happens every frame.

The `redraw_needed` flag is set on `commit()` (every client buffer commit), so a client in
a commit loop keeps the flag permanently true.

Risk level: Low. No security exploit path. This is a performance/resource bug.

## TDD Fix Plan

1. **RED**: Write a test that frame callbacks are throttled. Sending callbacks more than
   once per 33 ms (~30 fps) should be suppressed.
   **GENERAL**: Add `last_frame_callback_ms: u32` to `State`, initialized to 0.
   **verify**: `cargo test`

2. **RED**: Write a test that `frame_callbacks` skips sending when less than 33 ms has
   elapsed since the last callback batch.
   **GREEN**: In `frame_callbacks`, compare `time` against `last_frame_callback_ms`;
   if elapsed < 33 ms, return early without sending callbacks. Update
   `last_frame_callback_ms = time` when sending.
   **verify**: `cargo test`

3. **RED**: Write an integration test that a client committing continuously does not cause
   eswm to render more than ~30 times per second (measured via render call count).
   **GREEN**: The throttle in step 2 already enforces this at the frame-callback level,
   breaking the commit loop.
   **verify**: `cargo test`

**REFACTOR**: None needed. The change is minimal and localized.
