# CI incident: spec drift, then missing Lua 5.4

**Date:** 2026-11-26
**Scope:** `.github/workflows/ci.yml`, CI runs on `main`
**Verdict:** resolved — CI run `45762651715` is green at `291c41a`.

## Observations

1. `git push --all origin` published `main` (`b3854ff..e5cf74c`) and ten local
   branches. The pre-push `main` was `b3854ff`.
2. Historical failures (first seen `44941696174`, 2026-11-21) came from
   `python3 scripts/spec-lint.py`:
   - `release-plan: epic e08 has no specs/epics/e08-* capsule`
   - `execution-status: lists e08-panics-correctness with no capsule directory`
3. Commit `1eb6327` made the linter archive-aware and reconciled the planning
   SoT, but CI never re-ran because nothing had been pushed since. The push
   cleared both problems; the `Lint specs` step passed on run `45761351902`.
4. Run `45761351902` then failed at `Build` with exit 101:

   ```text
   error: failed to run custom build command for `mlua-sys v0.13.0`
   thread 'main' panicked at .../mlua-sys-0.13.0/build/find_normal.rs:63:30:
   cannot find Lua5.4 using `pkg-config`
   > pkg-config --libs --cflags lua54
   Package 'lua54' not found
   ```

5. The workflow's `pacman -Sy` list never named `lua54`. On Arch,
   `lua54.pc` is owned by the `lua54` package. The old failing run installed
   79 packages and happened to pull `lua54` in transitively; the new run
   installed 78 and lost it. A local `pkg-config --libs --cflags lua54`
   succeeds because the developer machine has `lua54` installed explicitly.

## Fix

Commit `291c41a` adds `lua54` to the explicit dependency list in
`.github/workflows/ci.yml`, with a comment explaining that `mlua-sys` asks
`pkg-config` for `lua54.pc`. The change is data-only: no logic, no API, no
test change. Skipped skills were justified in the commit body per
`quick-fix`.

## Follow-up rule

Any new system library consumed by a Rust `-sys` crate must be named
explicitly in the install step. Transitive `pacman` dependencies are not a
build contract — they change when the package set changes.
