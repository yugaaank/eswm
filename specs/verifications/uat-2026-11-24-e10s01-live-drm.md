## Setup

1. Start eswm on a TTY. Confirm the session is live (pointer moves, no errors in
   `~/.local/state/eswm/eswm.log`).
2. Open two windows and make them floating (`Super+Space` on each). Give them
   nonzero titlebar height via config if you want to test the top edge on the
   frame; the eight handles work with `titlebar_height = 0` too (top edge is the
   border strip).
3. Note each window's starting rect visually (or from the log's click trace).

## Eight handles

For each handle below, press on the edge/corner and drag ~100 px outward.
The **opposite edge must not move**; only the grabbed side(s) change.

| # | Handle | What must stay fixed | Cursor on hover/drag |
|---|--------|----------------------|----------------------|
| 1 | North (top edge) | bottom edge | `ns-resize` |
| 2 | South (bottom edge) | top edge | `ns-resize` |
| 3 | West (left edge) | right edge | `ew-resize` |
| 4 | East (right edge) | left edge | `ew-resize` |
| 5 | North-West corner | bottom + right edges | `nwse-resize` |
| 6 | North-East corner | bottom + left edges | `nesw-resize` |
| 7 | South-West corner | top + right edges | `nesw-resize` |
| 8 | South-East corner | top + left edges | `nwse-resize` |

The 6 px invisible padding outside each frame is part of the grab zone: a press
6 px outside an edge should start the matching resize. Titlebar buttons
(close/maximize/minimize) must still win over the padding — click each button
to confirm it fires and does not start a resize.

## Constraints and input semantics

9. **Minimum size** — shrink any handle far past the limit; width stops at
   200 px and height at 150 px (or the values set by
   `es.dsp.set_min_window_size(w, h)` in config). No flicker, no wrap to a
   corner, no `u32` underflow artifacts.
10. **Work area clamp** — grow past the output edge; the window stops at the
    work area and remains clickable (no off-screen wrap).
11. **Click without travel** — press on an edge and release without moving;
    geometry is unchanged (3 px threshold).
12. **Escape cancel** — start a resize, move ~50 px, press Escape; geometry
    returns to the pre-drag rect. The button is still physically held — release
    it and confirm the client did not start its own drag/selection.
13. **Cursor feedback** — near each handle the cursor changes to the mapped
    icon (table above); over free space it returns to the default arrow.
14. **Super+RMB** — with Super held, right-drag still resizes from the
    bottom-right corner (compatibility shortcut).
15. **Super+LMB** — with Super held, left-drag still moves the floating window.
16. **Client sizing** — after a resize the client surface actually reconfigures
    to the new frame (no frame-grows-around-stale-content like the old titlebar
    maximize bug). Check a GTK and a winit client if available.
